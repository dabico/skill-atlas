# 2026-10-01, GitHub token

A subagent built `feature/github-token` in `.claude/worktrees/agent-aeea0f9104b637abf`, off `origin/main` at `14c37f3`.

- `internal/repo/auth.go` holds `token()` (reads `GITHUB_TOKEN`, then `GH_TOKEN`, on every call), `tokenHost`, `authorize` and `listOptions`. `apiRequest` and `fetchArchive` call `authorize`; `lsRemote` takes its options from `listOptions`.
- `rateLimitError(reset, hadToken)` appends `; set GITHUB_TOKEN to raise the limit` only when no `Authorization` header went out.
- Tests in `internal/repo/auth_test.go` set the variables with `t.Setenv` and point `tokenHosts` at 127.0.0.1 to see the header on `httptest` servers. One test redirects to `localhost` and checks the header is dropped. Another keeps the default `tokenHosts` and checks no header goes to a non-GitHub host.
- `spec/cli.md` got a "GitHub token" section and new wording for the credential and rate-limit lines. `README.md` line about credentials was replaced; it still described the SSH agent.
- The network tests and the e2e suite weren't run here (the proxy blocks `codeload.github.com`).
- The skill `/anti-ai-writing-style` isn't installed on this machine, so the spec and PR text were written to the same rules by hand: short sentences, no filler.

## Review follow-up

The jetbrains-air bot left 2 comments on PR #12; the maintainer approved both.

- Private downloads: with a token, `archiveRequest` builds the request with `apiRequest` for `<apiBase>/repos/<o>/<r>/tarball/<sha>`. Without one it keeps `<archiveBase>/<o>/<r>/archive/<sha>.tar.gz` and sends no Authorization. 404, 401 and rate-limit handling match the listing (`rateLimited` is shared).
- Bad token: `errBadToken(name)` on a 401 when the token was sent. `token()` now returns the value and the variable name.
- `do()` wraps `httpClient` with a `CheckRedirect` that deletes Authorization for hosts outside `tokenHosts`. Go alone would forward it to a subdomain such as `codeload.api.github.com`; a mutation check (removing the delete) fails `TestDownloadWithTokenUsesAPI`.
- `fakeGitHub` in `auth_test.go` dials the test server for every host name, so tests use the real names `api.github.com` and `codeload.github.com` with the default `tokenHosts`.
- `fakeRemote` and `fakeAPI` now unset both variables, so the unit tests don't depend on a token in the developer's shell. Call `setTokens` after them.
