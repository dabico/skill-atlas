# 2026-10-01, GitHub token

A subagent built `feature/github-token` in `.claude/worktrees/agent-aeea0f9104b637abf`, off `origin/main` at `14c37f3`.

- `internal/repo/auth.go` holds `token()` (reads `GITHUB_TOKEN`, then `GH_TOKEN`, on every call), `tokenHost`, `authorize` and `listOptions`. `apiRequest` and `fetchArchive` call `authorize`; `lsRemote` takes its options from `listOptions`.
- `rateLimitError(reset, hadToken)` appends `; set GITHUB_TOKEN to raise the limit` only when no `Authorization` header went out.
- Tests in `internal/repo/auth_test.go` set the variables with `t.Setenv` and point `tokenHosts` at 127.0.0.1 to see the header on `httptest` servers. One test redirects to `localhost` and checks the header is dropped. Another keeps the default `tokenHosts` and checks no header goes to a non-GitHub host.
- `spec/cli.md` got a "GitHub token" section and new wording for the credential and rate-limit lines. `README.md` line about credentials was replaced; it still described the SSH agent.
- The network tests and the e2e suite weren't run here (the proxy blocks `codeload.github.com`).
