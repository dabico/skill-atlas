## Archive download

The maintainer picked option A for fetching: drop the clone and download the GitHub tarball of the commit, and narrow support to GitHub. Quote: "Let's go with option A and narrow support to GitHub for now." For SSH URLs they picked A again (treat them as HTTPS, no auth) and said token support (C) would be preferred: "Let's go with A for now, but C would be preferred." `GITHUB_TOKEN` support is the next PR.

A subagent built it in `.claude/worktrees/archive-download` (branch `feature/archive-download`):

- `internal/repo/download.go` replaces `clone.go`. `Download` lists refs with go-git's `ListContext` (HTTPS, no auth, `AppendPeeled`), picks the commit SHA, then streams `https://github.com/<owner>/<repo>/archive/<sha>.tar.gz` through gzip and tar into the target directory. It strips the top-level directory, writes only files and directories, skips symlinks and hard links, and fails on absolute paths, `..` escapes, a second top-level directory and a pax `comment` that isn't the resolved SHA. ls-remote, the archive base URL and the HTTP client are package variables, so unit tests use fake refs and `httptest` with in-memory tarballs.
- `ParseURL` accepts only `github.com` (any letter case) and an `<owner>/<repo>` path. `Target` lost `SSH` and gained `Remote` (the HTTPS URL) and `Owner`. SSH forms give the same `Display` and `Remote` as HTTPS, so the duplicate check still treats them as 1 repository.
- `cmd/skill-atlas`: `downloadFunc`, `Downloading <repo>…` progress, `--parallel` help says download. Tests that used `x.test` URLs now use `github.com`. The terminal check test uses fake deps, because `127.0.0.1` no longer parses.
- e2e: `cloneScan` became `downloadScan`, `cloneWait` became `downloadWait`, and the interrupt test waits for `Downloading`.
- Docs: `spec/cli.md` scan command, scope, state, TUI, report and exit code wording; `AGENTS.md` commands, layout and architecture rules; the CI network job is now "Network download tests (real GitHub)".

This machine's proxy blocks `codeload.github.com`, so real downloads fail here. Unit tests, lint and the ls-remote-only network tests ran locally. The download network tests and the e2e suite are left to CI.

The failed-repo error text in the `multi-repo-failed.png` screenshot comes from ls-remote and didn't change, so no baseline needed an update.

## Organization scan

PR #8 (archive download) was merged as `4e77a2a`. The maintainer asked for org support: "Implement support for organizations in GitHub. Submitting an organization URL downloads all skills from all repositories available to the requester. Refs should not be supported for this. If CLI has an org URL specified and a specific repository from that org is specified, then it's just ignored in favor of the org scan."

A subagent built it in `.claude/worktrees/org-scan` (branch `feature/org-scan`):

- `internal/repo/url.go`: `ParseURL` accepts `https://github.com/<org>` and returns a `Target` with `Org` set (no `Remote` or `Name`). SSH forms that name only an owner fail with a hint to use the HTTPS URL. `repoTarget` builds repository targets for both parsing and listing.
- `internal/repo/org.go`: `ListOrg` calls `GET /orgs/<org>/repos?type=all&sort=full_name&per_page=100`, follows `Link: rel="next"` (only on the API host) and returns targets named by `full_name`. Errors: 404, rate limit with the local reset time, other statuses, an empty org (`NoRepositories`). `apiBase` and `httpClient` are package variables for httptest.
- `internal/repo/download.go`: the empty-repository error wraps the new `ErrEmptyRepository`.
- `cmd/skill-atlas/org.go`: `checkOrgs` (ref and twice usage errors, drops covered repos before the duplicate check), `expandOrgs` (lists in order, prints `Listing repositories in …`, a failed org becomes 1 failed result), `dropEmpty` (leaves out empty listed repos, an all-empty org becomes the "no repositories found" failure). `deps` has `listOrg`. Failures not printed yet (failed orgs when alone at listing time, all-empty orgs, a failing repo next to a failed org) are printed after the downloads, with the prefix when there are several results.
- Tests: URL parsing, httptest listing (3 pages, errors, cancel), `TestListOrgNet` against `agentskills`, cmd tests with fake deps, an htmlreport test for a failed entry without ref, and e2e `TestHTMLOrg`.
- Docs: `spec/cli.md` has an Organizations subsection and "1 result" wording; `AGENTS.md` layout and architecture rule.

The real run of `scan --html https://github.com/agentskills` listed 2 repositories (`agentskills` and `.github`), then both downloads failed on the codeload proxy block, as expected here.
